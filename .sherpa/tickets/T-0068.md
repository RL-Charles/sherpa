## Expected

`shp hooks install` leaves a hand-written "## Work tracking (Sherpa)" section alone and only refreshes sections Sherpa generated.

## Actual

It reported `↻ docs updated AGENTS.md` and replaced the section with the generic protocol, dropping repo-specific rules.

## Repro

1. Write a section under "## Work tracking (Sherpa)" that does not start with the generated opener.
2. Run `shp hooks install`; AGENTS.md is rewritten.

## Context

- Affected: main after PR #11 (T-0067 loosened the guard); older builds replaced any section missing shp brief/where add.
- First seen: 2026-11-03, applying review policies across projects.
- Related tickets: T-0067.

## Design

### Shape
upsertProtocol: unchanged if the current protocol is present; a section under the heading is replaced only when it opens with protocolOpener; with no heading, a file that already covers shp brief + shp where add is left alone; otherwise append.

### Invariants
- Hand-written protocol sections are never rewritten.
- Generated sections still pick up new protocol text.

## Out of scope

- Recovered calametra AGENTS.md with git restore; it was clean before the install.

## Risks

- Detection relies on the generated opener; a user who keeps it but edits inside the section still gets it replaced.
