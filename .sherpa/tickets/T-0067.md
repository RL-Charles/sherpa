## Why

Every ticket an agent finished waited for a human by default, unless a project wrote an `auto_done` allowlist. That queued low-risk work behind people and trained them to rubber-stamp. Flipping the default lets verified work land on its own, and keeps human attention for what each project names as risky: migrations, deploys, dependencies, auth, big diffs. Humans then audit a sample after landing instead of gating every change.

## Context

- Background: T-0063 added the `auto_done` allowlist; T-0046 lets agents close tickets on evidence; T-0054 added agent review.
- Constraints: stories and epics stay human-only (user decision, 2026-11-03); manual checks stay human-only.
- Prior art: Lauren Tan's pstack: agents verify before merge, humans sample after landing, reversible vs irreversible changes, and recurring mistakes become rules.

## Design

### Shape
Default flips from allowlist (auto_done) to denylist (human_review). A ticket closes on a passing agent review, or on an agent's `shp done`, unless policy.Human returns a reason.

    shp submit ──▶ agent_review ──▶ shp review --pass ──▶ policy.Human(it, all, Change)
                                                          ├─ "" ──▶ done ──▶ afterAgentClose: commit (auto) · sample ⚑
                                                          └─ why ─▶ review (human)

### Types and enums
    type Rule struct { Name string; Labels, Under, Paths []string; MinLines int }
    type Policy struct { HumanReview []Rule; Commit string /* auto|off */; Sample float64; Verify string; Found bool }
    type Change struct { Lines int; Files []string }

### Invariants
- Stories and epics never close by an agent (workflow.CheckDone and policy.Human both say so).
- Unresolved or missing deliverables/checks and open manual checks always wait for a human.
- Every condition in a rule must hold; "or" is several rules. A rule needs at least one condition.
- `auto_done` is refused with a migration hint: silently ignoring it would loosen a project's review.
- Sampling is stable per ticket ID (fnv hash), so re-closing never changes the pick.
- Commit only touches the submitted files plus the ticket markdown; other dirty or staged files stay out.
- Commit and sample failures warn; the close stands.

### Contracts
- paths match submit files ∪ code map; `**` spans directories; a slashless pattern matches the base name.
- `shp policy init` refuses to overwrite without --force; --verify "" clears the guess.
- Audits are human-only; `--reopen` moves the ticket back to in_progress.

### Alternatives
- Risk tiers (T0–T3): deferred; rules + sample cover the cases without a scoring model.
- Interactive prompts in `policy init`: rejected; agents run it non-interactively, so the session-start nudge has the agent ask the user and pass flags.

## Out of scope

- Risk tiers and multi-model review panels (pstack `interrogate`); rules + sampling first.
- `commit: pr` (branch + PR per ticket); only `auto` and `off` for now.
- A TUI view for the audit queue; `shp context` and `shp policy audit` list it.

## Risks

- Breaking: projects with `auto_done` get an error until they migrate (deliberately not ignored).
- Projects without a policy now auto-close; session start and `hooks install` flag them until `shp policy init` runs.
- `commit: auto` commits from the reviewer's process; a failing commit-msg or pre-commit hook only warns.
