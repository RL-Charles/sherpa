## Description

The same Sherpa hook logic, installed in each tool's native format, so every agent gets the same guardrails as Claude Code:

| Tool | Where | How |
|---|---|---|
| Claude Code | `.claude/settings.json` | hooks (reference implementation) |
| Codex | `.codex/hooks.json` | Claude-shaped hooks |
| Cursor | `.cursor/hooks.json` | `sessionStart`, `preToolUse`, `afterFileEdit`, `afterShellExecution`, `stop` |
| OpenCode | plugin (`internal/hooks/templates/opencode-plugin.ts`) | TS plugin calling `shp hook` |

Each adapter parses its tool's payload into one shared event (session start, pre-edit guard, post-edit log, stop), so the rules live once in `internal/hooks/hooks.go`.

## Why

Sherpa's work protocol only holds if the agent's tool enforces it. S-006 started with Claude Code; this brings Cursor, Codex and OpenCode to parity so a team can mix agents on one board and get the same start → log → submit trail from each.

**Open for review:** verified by live block + recovery runs in all four tools and `TestAdaptersParse/Write`. Cursor may drop `sessionStart` context (a known Cursor bug; AGENTS.md covers it). Re-test block + recover in Cursor and OpenCode if their versions moved.
